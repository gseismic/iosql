## 1. 设计输入卡

> 为 **金融时序库用户（数据工程师 / 量化研究员 / 存储运维者）** 在
> **① 入库后确认数据质量（高频）② 策略前探索·筛选·导出数据（最高频）③ 布局诊断与受控维护（低频高危）**
> 场景下设计 **本机桌面浏览器 Web 管理台（主目标 1440×900）** 界面；
> 品牌约束 **有：沿用现有暗色「精密仪器面板」token 体系**；内容密度 **中高**；存量系统 **已勘察，见现状认知卡**。

场景来源：v1 设计文档 §2 的四类用户画像经实现验证仍然成立，本文按频率合并为三场景，跳过重新推导。

### 2.3 痛点清单（截图 + 代码证据）

| # | 层 | 痛点 | 证据 |
|---|---|---|---|
| T1 | IA | **Browse Data 与 Query 功能重叠约 70%**（条件构造器 + 结果表格 + limit + 导出全部同构），用户面对"看数据去哪页"的决策成本；Query 独有价值只有 Explain 和时序快捷区 | `tab-browse.js` 625 行 vs `tab-query.js` 227 行共用 ConditionBuilder |
| T2 | IA | **Overview 首屏信息价值低**：3 张统计卡 + 表清单后大面积留白，没有回答 P1 场景"数据进对了没有"——无时间范围、无分区偏斜信号、无健康度指示 | 截图 overview：下方 55% 空白 |
| T3 | 时序 | **毫秒时间戳泄漏到 UI**：Query 的 start/end 要求输 `1735689600000`；Structure 的分区 chips 是原始毫秒；Charts X 轴标签 `1735747200` | `tab-query.js` placeholder、`tab-structure.js` parts chips、`tab-charts.js` axes values 强制 `String(Math.round(v))`（`x.time=true` 也没走 uPlot 时间轴） |
| T4 | Charts | **默认值错误**：数值列默认选中时间列本身（画 date 折线，无意义）；symbol 不填时多线混叠无区分说明 | 截图 charts：一条无意义斜线 |
| T5 | IA | **Browse 内两套过滤并存**（列头过滤器 + 条件构造器），状态互不同步 | `tab-browse.js` filter-row + builder 双份状态 |
| T6 | Structure | v1 设计文档承诺的"分区行数迷你条形图直观看偏斜"**未实现**，parts 只是 chips，偏斜要靠脑补 | 对比 §6 Tab3 设计 vs `tab-structure.js` |
| T7 | 状态 | 空态单薄（"暂无表"一句话，无引导）；Overview 统计失败显示 — 无重试入口 | `app.js` renderSidebar |
| T8 | 视觉 | 首屏 stat-card 视觉弱、层级平；快捷键提示常驻顶栏占用黄金位置，价值低 | 截图 |

不做清单（保持现状）：双模式安全模型、keyset 分页、API 面、零构建链技术栈、暗色单主题——本次重构**不动后端**（除 1 个可选的时间格式解析辅助），纯前端重构。

## 4. 核心重构决策：6 Tab → 5 Tab

```
现状： Overview | Browse Data | Structure | Query | Charts | Maintain
方案： Overview | Data | Structure | Charts | Maintain(仅 write)
                    └────── 吸收 Query ──────┘
```

| 决策 | 内容 | 理由 |
|---|---|---|
| D1 `[假设]` | **合并 Browse+Query 为单一 Data 页** | 消除 T1。表格是唯一主角；Explain 变为工具栏按钮，结果以可折叠面板出现在表格上方；时序快捷（date/session/symbols/latest 截面）收进工具栏的"时序"分段，普通表自动隐藏 |
| D2 | **Overview 升级为驾驶舱**：表卡片网格（行数/分区数/时间范围/健康信号/快捷入口） | 消除 T2，首屏直接回答 S2"进对了没有" |
| D3 | **时间语义统一**：新增全局时间输入组件（接受 `2025-01-05`、`2025-01-05 10:30`、`1735689600000`，回显解析结果）+ 所有时间戳展示默认可读化 + Charts 启用 uPlot 原生时间轴 | 消除 T3/T4 的根因；量化研究员不需要知道毫秒 |
| D4 | **Structure 补齐分区偏斜可视化**：parts chips → 分区表（可读时间 + 行数条形图 + segment 数） | 消除 T6，兑现 v1 承诺；这是 iosql 区别于通用 SQLite 工具的特色页 |
| D5 | **Browse 过滤收敛为一套**：列头过滤为主（快），条件构造器收进工具栏"高级条件"（强），二者并在同一 where 预览条中可见 | 消除 T5 的状态分裂：两入口、一个真相（合并后的 where 数组） |
| D6 | **Tab 顺序按场景频率**：Data 是表级默认落点（S1 最高频），Charts 紧随，Maintain 仍殿后且只读锁态 | 最短路径让给最高频场景 |
| D7 | Charts 默认值修正：数值列默认第一个非时间数值列；symbol 默认列表第一个；X 轴时间可读化 | 消除 T4 |

## 5. 页面清单与低保真结构

### P1：Overview 库驾驶舱（库级）

- **服务场景**：S2 第 1 步（启动即看）
- **进入来源**：启动默认 / 左栏"总览"；**离开去向**：点表卡 → P2 Data，点健康信号 → P3 Structure
- **频率** `[估算]`：每次启动 1 次 + 回灌后刷新
- **信息优先级**：
  - P1：表卡片网格（行数、分区数、时间范围、健康信号）
  - P2：库级汇总行（表数/总行数/模式/URI）
  - P3：导出库级操作（无）——不放任何库级写操作
- **主行动点**：点表卡片进入 Data（整卡可点）
- **布局模式**：仪表盘（卡片网格）

```
┌────────────────────────────────────────────────────────────────┐
│ 库级汇总行: 3 张表 · 2,119 行 · READ-ONLY · /tmp/…  (P2 弱化)   │
├────────────────────────────────────────────────────────────────┤
│ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│ │ ticks  [时序]│ │ daily_bars ▁▂│ │ events      │  (P1 卡片网格) │
│ │ 1,460 行     │ │ 600 行       │ │ 59 行        │               │
│ │ 10 分区 ⚠偏斜 │ │ 5 分区       │ │ 无分区       │               │
│ │ 01-01~01-10  │ │ 01-01~04-30  │ │ —           │               │
│ │ duration(1d) │ │ duration(1mo)│ │ —           │               │
│ └─────────────┘ └─────────────┘ └─────────────┘               │
│  ⚠ = 最大分区/中位行数比超阈值，悬停见详情，点击去 Structure     │
└────────────────────────────────────────────────────────────────┘
空态(库中无表)：引导语 + 建表命令示例             加载态：卡片骨架屏
错误态(stats 失败)：卡片正常展示，行数位显示"统计失败 + 重试"按钮
极端(>30 表)：自动切换为紧凑表格视图（同 v1 清单列 + 时间范围列）
```

### P2：Data 数据工作台（表级，合并 Browse+Query）

- **服务场景**：S1 全部步骤；S2 第 3 步（抽样核对）
- **进入来源**：左栏点表 / Overview 卡片；**离开去向**：Tab 切换 / 单元格侧滑
- **频率** `[估算]`：最高频，每个交互的核心页
- **信息优先级**：
  - P1：数据表格（keyset 分页、排序、时间可读化）
  - P2：过滤（列头快筛 + 高级条件）、导出、Explain、时序快捷
  - P3：列显隐、页大小、每列统计（收纳进"⚙"菜单）
- **主行动点**：查询（回车即发 / 应用筛选）
- **布局模式**：工具栏 + 表格 + 分页（DB Browser Browse Data 心智）

```
┌────────────────────────────────────────────────────────────────┐
│ [浏览|时序|截面] ← 分段控件(仅时序表出现，默认浏览)               │
│ ┌─ 筛选预览条: where AND symbol='AAPL' AND ts>…  [复制] [清空] ─┐│
│ ├──────────────────────────────────────────────────────────────┤│
│ │ 浏览视图:                                                     ││
│ │   表格(列头排序 + 列头快筛行)                                   ││
│ │   工具行: [⊕高级条件▾] [Explain] [导出▾] [⚙列]  行数: … [分页]  ││
│ │ 时序视图(切1): date[2025-01-01~] session[ ] symbols[多选]      ││
│ │ 截面视图(切2): as_of[日期时间] by[symbol] columns[ ]  [查截面]  ││
│ └──────────────────────────────────────────────────────────────┘│
├────────────────────────────────────────────────────────────────┤
│ [Explain 折叠面板: 候选/扫描/跳过 + skip_reasons（用时展开）]      │
│ 数据表格（同现状 keyset 分页 + 单元格点击侧滑详情）                 │
│ 分页条: ‹ 1-200 · 共 1,460 · ›    [←/→ 快捷翻页]                 │
└────────────────────────────────────────────────────────────────┘
空态(查询 0 行)：说明筛选无命中 + [清空筛选] 引导按钮
加载态：表格区域 spinner + 禁用翻页（同现状）
错误态：422 keyset 不可排序 → 列头禁用划线（保留现状机制），toast 带原因
```

### P3：Structure 结构透视（表级，iosql 特色）

- **服务场景**：S2 第 2 步（契约核对）、S3 第 1 步（布局诊断）
- **信息优先级**：P1 分区分布表（偏斜可视化）；P2 契约卡、segment 表；P3 stats 明细（details 折叠，现状保留）
- **主行动点**：无执行类（诊断页），行动点为"点击分区行 → 带 partition 筛选跳 Data"
- **布局模式**：分层详情（契约 → 分区 → 段，三层从逻辑到物理）

```
┌────────────────────────────────────────────────────────────────┐
│ 契约 SPEC（现状 kv 卡保留，压缩为两行网格）                        │
├────────────────────────────────────────────────────────────────┤
│ 逻辑分区 PARTS (5)                    [含 obsolete ▢]           │
│ partition      行数        ▮▮▮ 条形图(相对最大分区)  segments    │
│ 2025-01-01      55  ▂                            1              │
│ 2025-04-25     260  ████▆ (偏斜高亮⚠)             1              │
├────────────────────────────────────────────────────────────────┤
│ 物理 SEGMENTS（现状表保留：file_key/rows/state/时间范围/stats）    │
└────────────────────────────────────────────────────────────────┘
```

### P4：Charts 时序快览（表级）

- **服务场景**：S1 第 4 步（走势快览）
- **信息优先级**：P1 图表主体；P2 配置行；P3 对数轴/桶数（收进配置行尾）
- **主行动点**：绘制
- **布局模式**：配置 + 画布

┌────────────────────────────────────────────────────────────────┐
│ 图型[line|candle] 数值列[close▾(默认第一个非时间数值列)]           │

│ uPlot 画布：X 轴走原生时间轴（01-01…04-30 可读）                   │

└────────────────────────────────────────────────────────────────┘

### P5：Maintain 维护台（表级，仅 write 模式）

- **服务场景**：S3 第 2-3 步（诊断后的受控执行）

## 10. SQLiteBrowser 逻辑研究与定案（2026-09-28）

> 用户要求：研究 sqlitebrowser 的逻辑，从真实用户使用场景决策。研究材料：官方 wiki
> （Browse-Data / Using-the-Filters / Plot-Dock 页）、GitHub issues、本机真实使用信号。

### 10.1 研究发现：SQLiteBrowser 的五条核心逻辑

| # | 逻辑 | 证据 |
|---|---|---|
| L1 | **一网格主义**：Browse Data 网格是全应用中心表面——排序、筛选、编辑、绘图、导出全部围绕同一网格；Execute SQL 是唯一平行表面（服务"写代码"心智），其结果也汇入同一网格形态。Plot Dock 不是独立 Tab，是网格的附属 Dock（Ctrl+D），数据永远取自当前网格 | wiki Plot-Dock："浏览要用于绘图的表，或执行将提供绘图数据的查询"；列列表反映"当前浏览的表或刚执行的查询" |
| L2 | **轻筛选、就地微语法**：不做筛选表单，在列头输入框内联微语法——`> < >= <= = <>`、`1~5` 范围、`/regex/`、`%` 通配符、右键 "Use as Exact Filter"；**auto-apply 边打字边筛**（防抖可配置）。十年痛点全部集中在这一行输入框：AND-only 组合（官方文档自认"常见困惑点"）、#1189 空值过滤、#1522 正则、#3995 状态被覆盖、#1187 焦点即触发查询的骚扰 | wiki Using-the-Filters；issues |
| L3 | **快览定位的图表**：Plot Dock 官方措辞是"简单图表"，X 轴原生识别 Date/Time/Numeric/Label，不做专业绘图 | wiki Plot-Dock："quick assessment" 定位，样式仅线型/点形/颜色 |
| L4 | **可重复性是一等诉求**：排序/筛选/列宽存入 Project Files；CLI `-ro` 拖了多年（#3760）才补上，说明用户要"可重复的打开方式" | wiki Browse-Data（排序设置保存到 Project Files）；#3760 |
| L5 | **本机真实使用铁证**：用户在真实生产库（`/media/lsl/Z1/.../binance/future_usdt/kline.factor.iosql`，kline_factor_1m 表 31 个月度 segment / 839MB）上**绕过 iosql UI，直接用 sqlitebrowser 打开物理 segment 文件** `data/1640736000000.sqlite3` 看原始行——"看原始数据"的体验基准就是 DB Browser 打开单文件的速度与顺滑度 | 本机进程观察 + 库规模实测 |

### 10.2 定案（关闭 §8 全部开放问题）

| 问题 | 决策 | 依据 |
|---|---|---|
| A1 合并 Browse+Query | **确认合并为 Data 页** | L1 一网格主义：条件构造器/时序快捷/截面都是"产生行的方式"而非独立页面意图，产出汇入同一网格；iosql 无裸 SQL 面，Query Tab 本就是 Execute SQL 的受控替代物，更没有理由维持两个平行入口 |
| Q1 时序快捷形态 | **确认分段控件（浏览\|时序\|截面）** | L1 的反面教训：Plot Dock 藏在 Ctrl+D 后导致大量用户不知道它存在。分段控件让三种行产生方式可见可切；三者同输出（网格），切换零学习成本 |
| Q2 URL 带筛选状态 | **确认做**（hash 携带 partition/筛选/symbol） | L4：DB Browser 用 Project Files 解决可重复性，iosql 的 hash 路由零成本对齐"可收藏、可分享、可回到同一视图" |
| Q3 K 线实现 | **维持四线近似，X 轴原生时间轴必修** | L3：快览定位下四线近似够用；但 Plot Dock 的 X 轴类型识别是底线能力，现状强制 `String(Math.round(v))` 必须改为 uPlot 原生时间轴 |
| 新增 D8 | 列头快筛微语法文档化 + 保持（现状已实现 `>100`、`1~5`、`a,b`） | L2：与 DB Browser 心智一致，降低学习成本 |
| 新增 D9 | Explain 做成网格附属可折叠 Dock（学 Plot Dock），不常驻占位 | L1：附属面板而非独立区块 |
| 新增 D10 | 列头筛选 auto-apply（300ms 防抖），替代现状手动"应用筛选" | L2 + #1187：auto-apply 是十年验证的默认，防抖规避 #1187 式骚扰 |
| 新增 D11 | 性能基准：真实库（31 段/839MB）Data 页筛选→出行动 < 3s | L5：达不到基准用户就绕回 sqlitebrowser 直接开 segment 文件 |
| 新增 D12 | **列选择器（用户明确需求：未来面对几百列，只显示特定若干列）**：Data 工具栏「⚙ 列 x/y」入口 → 下拉面板 = 搜索框（就地过滤列名）+ 快捷批操（全部显示/恢复默认/仅键与时间列）+ 类型标注复选列表；勾选即改实时生效；宽表默认只显示缺省列集；最少保留一列；实现稿需把列显隐状态写入 URL（沿用 Q2 可重复性结论），500+ 列时列表虚拟滚动 | 用户 2026-09-28 明确提出；计数常显（x/y）让"当前看了几列"始终可感知；原型已在 122 列宽表演示 |
