# 全库审查修复：发布、扫描与不可变 Parquet 追加

## 不变式

操作范围与用户选择一致；构建中的 compact 文件不进入可见 manifest；新旧集合在一个 SQLite 元数据事务内切换。重命名独立维护 `namespace_revision`，避免改变现有物理 generation 指针的身份约束。普通读取以库租约保证维护互斥，读取流始终显式释放文件和连接配额。

## 查询与写入

显式写入 mode 只解析一次。strict 在创建任何数据文件前校验整批字段。统计仅在输入值与持久类型可证明一致时用于裁剪，旧 manifest 中不可信的 text/数值统计保守扫描。投影在逻辑列层校验，物理列引用使用限定标识符，防止 SQLite 双引号字符串兼容行为。

无序扫描使用单连接、单语句及 fetchmany；无序 LIMIT 逐文件递减。latest 在各文件内使用窗口排序，只把每组候选送入 Python；常驻内存与组数有关。compact 在临时 SQLite 文件中外部排序，行数据只保留固定读取批和一个目标 chunk，另保留与 segment 数量有关的发布元数据；临时磁盘需求与待整理分区大小有关。upsert 按主键中的分区列直达文件，只读取输入主键命中的行。

局部主键布局的 Web 游标追加文件身份，并绑定文件布局与排序。完整排序键为业务排序列、主键、物理文件；同一文件内主键唯一，因此合法跨文件重复行可逐一访问。布局变化时返回明确的游标失效错误。

## Parquet 追加格式

保留原有物理 `.parquet` 入口，第一次写入仍产生普通 Parquet 文件。追加批次写为不可变数据片，保存在该入口专属的隐藏目录中；原子 JSON 清单列出当前可见文件。读者使用清单中的文件集合，schema 演进用 union-by-name 并补 NULL。

append/ignore 只构建输入批，使用执行器的主键半连接检查历史键，不加载或重写历史完整行。replace/delete 仍可能重写受影响物理集合，但新集合先写到独立数据片，最后原子切换清单。清单发布前失败只产生不可见孤儿文件，旧集合继续可用。切换前先 fsync 数据文件和目录，清单持久化后可清理不再引用的数据片；清理失败不撤销成功发布。

追加的数据写出量与输入量线性相关。主键查重仍可能扫描历史键列；这不承诺全局常数时间索引。DuckDB 每连接内存上限沿用 256MB，排序/连接可使用临时磁盘。累计数据片可通过 compact/repartition 合并；维护清理、备份、迁移、rename、统计缓存与校验必须同时识别清单及其引用。

## PostgreSQL 控制会话

控制连接仅在未持锁、autocommit 的空闲状态下复用，使用有界缓存；每次独立 API 仍重新取得 advisory 锁并读取 generation。不得缓存“控制表不存在”跨调用。断连或解锁失败直接丢弃会话；关闭 Database/Table 清理对应空闲会话，fork 子进程断开继承 socket 而不向父会话发送解锁。连接与 SQL 次数、迁移互斥在真实 PostgreSQL 上验证。
