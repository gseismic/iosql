## 场景与契约

- 已有本地库通过普通路径或 `iosql:///绝对路径` 定位，打开时根据库自身身份识别 SQLite/Parquet；读、写均沿用识别出的引擎。
- 原 `sqlite://`、`sqlite3://`、`parquet://` 保持支持；新增 `iosql+sqlite://`、`iosql+sqlite3://`、`iosql+parquet://`，显式类型用于创建并在打开已有库时作严格断言。PostgreSQL 保留原连接 URI，`iosql+postgresql://` 作为同义写法。
- 新库可用显式前缀确定引擎，或通过独立创建接口/目标引擎参数明确指定。无类型的路径无法识别尚不存在或未初始化的库时应报错，不猜测文件名或默认 SQLite。
- 一个本地库只能有一种业务数据引擎。错配、未知、损坏、混合均须拒绝，不返回伪造的空表列表、不静默切换或转换。业务格式转换使用独立迁移目标。
- `iosql web` 支持以路径自动识别或显式指定 SQLite/Parquet；其他命令不能仅因能识别而错误执行不支持该后端的操作。

## 实现取舍

只比较表级 manifest 可兼容已有库，但空库和声明后尚未写入的 SQLite 空表没有持久化类型，且不同表名可以混用；仅靠 URI 则无法自动识别。采用库根的 `__iosql_database__.json` 作为新库权威身份，并保留表级标记核对。标记使用已经禁止表名使用的 `__` 前缀，避免与历史合法表名冲突。旧库无库级标记时只读扫描各表 manifest：有效旧 SQLite 表缺 `storage_engine` 按现有契约解释，其他无法确认或混合的情况报错。只读识别不重写旧库。

首次声明表或显式创建时，在库协作租约和跨进程初始化锁保护下确认/持久化类型；已经打开的不同后端句柄再次创建或写入时也不得绕过该约束。标记须随快照、重命名和 SQLite 代际发布复制；Parquet 平坦发布须在可重放的提交决定后发布标记，失败前不得修改已有目标。泛型 URI 在恢复屏障下识别实际引擎，不能因暂存状态把未完成的发布误认为空库。

识别、表构造和初始化使用独占的类型锁；表修改期间持有共享的类型锁，避免扫描读到尚未完成的元数据，同时允许不同表并行写入。锁按实际库路径跨进程协调，fork 子进程关闭继承的描述符，不能释放父进程的锁。长时间写入可能使类型识别等待，超时后明确报错。
