# Charts 保留原始点设计

日期：2026-09-29

## 背景与实测证据

用户的核心场景是金融指标可视化，要求所选时间范围内不抽样、不遗漏任何原始记录。
当前 Charts 实现走 `aggregate_by_bucket()`，默认 `buckets=2000`，每桶对指标求平均；
横坐标则使用桶中点，并非原始时间戳。

对用户指定的 `kline.factor.iosql` 做只读浏览器实测：

- `kline_factor_1m` 有 4,183,200 行、29 列（含主键），时间列为 `open_time`，主键为
  `(symbol, open_time)`，指标列包含 SMA、RSI、EMA、MACross、ATR 和 FutureATRBoundTrigger。
- 表中有 8 个 symbol。全范围 2022-01-01 00:00:00 UTC 至 2022-12-31 23:59:00 UTC。
- 当前默认 `SMA(20)[close]` 请求返回 2,000 点；未指定 symbol 时八种资产被合并到一条桶均值线，
  例如响应首尾 x 是 `1641003083985` 与 `1672523258014`，均为合成桶中点而非实际 `open_time`。
- 单 symbol 实际行数为 518,400 或 525,600；抽样会丢掉绝大多数分钟记录，也抹平短时变化。

## 目标

1. 每个被筛选到的原始行均进入图表输入；不做分桶、均值、抽点或静默截断。
2. 不指定 symbol 时，各 symbol 分别成线；绝不把不同资产的指标值平均到一起。
3. 横坐标使用真实时间/数值列。数值为空时保留该 x，并以图表间隙表示，不转换成 0。
4. start/end 与拖拽缩放限定查询范围，但在该范围内仍传输全部原始记录。
5. 用流式响应和批次解析避免服务端一次性构造百万行 JSON；浏览器只保留绘图所需的紧凑 x/y 数组。
6. 客户端取消图表流时释放有序读取器的只读连接；SQLite 迭代器在线程池中可能由不同串行工作线程恢复和关闭。
7. 图下注明真实点数与序列数，且能直接核对每序列点数。

## 方案

### 服务端

- line 响应改为 NDJSON：首行发送图型、列名、x 列等元信息；随后按批发送
  `{symbol, points:[[x,y], ...]}`；结束行发送总行数、各 symbol 点数与范围。
- 使用列投影，只读 symbol、x、所选指标，并沿用 symbol/start/end 过滤和分区裁剪。
- 每条记录原样输出，不调用 SQL 分桶聚合；`buckets` 不再控制 Charts 数据量。
- 对同一 symbol 的 x 顺序作校验；无效 x 或非数值 y 显式报错。null y 作为空值点传递。
- candle/OHLC 接口也需逐行输出所有 OHLC 观测，不保留旧的 2000 桶聚合路径。

### 浏览器

- `fetch()` 读取 NDJSON 流，按 symbol 增量填充扁平 x/y 数组；不创建每点一个对象的中间结构。
- 不指定 symbol 时服务端/前端按 symbol 形成独立序列。多序列横坐标不一致时做有序合并，缺失值填 null。
- 删除无效的 buckets 配置；状态行显示「无抽样」和每序列/总点数。
- 缩放事件仍按可视区重查，但可视区内返回全部原始行；双击复位重查全范围。
- null/non-finite 值作为断点处理，禁止 `Number(null) === 0` 造成假零值。

## 性能与边界

- 本地浏览器需实测 4,183,200 个点的加载、JSON 解析、uPlot 渲染耗时和控制台错误；不得通过降采样通过性能验收。
- 多 symbol 使用共享 y 轴时，量纲差异大的币价线可能压扁低价资产；界面应提示用户按单一 symbol 查看，或选 RSI 等可比指标。
- 用户数据中 4 个 symbol 有 525,600 行、4 个有 518,400 行；验收以 API 计数与源表按 symbol 的精确计数一致为准。
- 图上像素有限，多个相邻点可能重叠；这是显示分辨率导致的覆盖，不代表数据被抽掉。缩放后必须能查询并渲染窗口内所有原始点。
