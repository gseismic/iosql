## 完成内容

普通 SQLite legacy 文件查询现在先利用保存的分区边界定位文件，然后直接执行原 SQL 条件，不再为准备查询计算时间范围、全列 MIN/MAX、session 范围和 COUNT。用户业务的 CSV 全主键检查得以保留，同时消除了检查前的额外数据扫描。

- `iosql/engines/sqlite/table.py:3106`：带 where 的 select/query/latest/条件删除统一使用 lightweight legacy 引用。已有 row Segment 的 manifest 统计继续参与裁剪。
- 同文件 `:1566`、`:1605`：无条件迭代和显式 `count_rows()` 同样不预扫描统计；COUNT 仅在用户明确请求计数时执行。
- 同文件 `:2252`：explain 保留诊断统计展示，但裁剪决定使用与实际查询一致的引用，避免声称普通执行会按临时统计跳过文件。
- 同文件 `:2952`：已登记 legacy 文件缺失时保留引用，由已有完整性检查报错；正常 Segment 布局仍允许同名 legacy 文件不存在。索引/补列路径增加存在性检查，避免重建缺文件掩盖损坏。
- 更新两个 SQLite 回归测试文件与 iosql skill 的设计约束、性能说明。公开方法和参数没有变化。

该实现不建立新的查询时统计缓存。显式 `segments()`、布局/校验和 explain 等诊断仍可计算完整统计；其既有统计缓存的 WAL 失效机制没有在本轮重写，普通查询/删除已经不依赖该 legacy 缓存来排除文件。
