## 目标与范围

## 实施前自查与方案

1. 首次发布旧内容在独占锁内退休到稳定协调空间的本任务唯一目录，锁外清理只访问退休路径；不能在锁外按可复用的逻辑 URI 删表。中断后仍按提交决定恢复，退休失败保留旧内容并报告，不撤销提交。
2. 快照过滤区分普通侧车文件和业务目录；合法的 `-wal`、`-shm`、`.iosql-locks` 表不得漏拷，合并和备份均覆盖。
3. 库级锁增加 Windows 原生共享/独占字节范围锁，保持非阻塞尝试、总期限和显式解锁；POSIX 保留 flock。Windows 本地路径同时统一大小写身份。目录同步做平台适配，明确 Windows 未进行原机及断电验证。
4. allow_empty=True 仅接纳经过验证的 scaffold-only 空库，不放宽任意目录的接管检查。
5. generation 刷新保留未物化表的内存声明；Database 缓存刷新也必须保留这些句柄，持久新契约优先于旧声明。
6. 内部 rename/reconnect 不留下用户显式关闭标记；覆盖普通表重命名、普通库重命名以及显式重连后再迁移。
7. calendar 分区范围继续采用既有的毫秒格式，仅在分区裁剪比较处把秒级条件换算成毫秒；segment 的实际值统计仍按秒比较。这样同时修复已生成的秒级 manifest，不改写业务数据。覆盖 SQLite/Parquet、有无 segment、重开及范围查询。
8. ui 与 web 均不持有服务生命周期的共享租约，业务请求仍遵守库入口租约。

### 针对性验证后的补充

Parquet 的复制不携带表锁文件，读取入口应能安全重建它；现有空表已有持久契约但可能没有 data 目录，深校验应在确认没有任何数据文件引用后接受这种空表，新声明同时建立空 data 目录。测试不把 Parquet 的已持久空表误认为 SQLite 式的纯 scaffold。
