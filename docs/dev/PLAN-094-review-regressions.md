# PLAN-094 修复 SQLite 审查回归

- 日期：2026-10-28。
- 基线：提交 `3425277` 的六项后续审查意见；工作区已有的 PLAN-092 及测试记录不属于本次修改。
- 目标：修复主键匹配与数据保留、连接配额死锁、空表查询和投影语义回归，保持既有公共接口及性能约束。

## 实施与验收

1. 检查物理 SQLite 列声明和类型亲和性，修复临时主键归一化；以原生 SQLite 比较为依据覆盖 NUMERIC/DECIMAL 大整数、数值字符串和混合类型，检查 segment ignore 及 upsert 数据保留。
2. 内部主键查询使用绑定字面量，覆盖形似字段引用的字符串、BLOB 和复合主键；尚未创建物理文件的首次 upsert 可完成类型推断。
3. 消除迭代器产出批次时消费者的连接配额自锁，覆盖单连接配置下的读取、写入、save_as、提前关闭和超时；同时保留有序/无序流的既有资源与性能约束。
4. 未推断列的空时序表允许 latest 返回空结果；已定义或已写入表仍校验不存在的分组列及投影。
5. 保留列表混合通配符的查询语义并验证逻辑列，覆盖重复通配符及特殊列名，杜绝静默缺列与非法 SQL。
6. 对改动自审，运行定向回归、相关测试及完整测试套件；若发现偏离则更新计划并修正，最后记录实际结果和验证边界。

单连接无序流采用临时文件暂存每个物理文件的读取结果，在向消费者交出批次前释放连接；读取仍保持单游标和有界内存，但首批可能需要等待整个物理文件读取完毕，临时磁盘用量随结果增长。其他并发流占满预算时，后续连接申请快速报错，防止配额自锁。

实施、自审及验证已完成；完整测试结果与边界见 [PLAN-094-review-regressions-OUTCOME.md](PLAN-094-review-regressions-OUTCOME.md)。

## 自审补充

- 首次 segment ignore 的去重与类型推断共用同一组列类型；Parquet 空表元数据不代表已有数据文件。
- 已登记但缺失的 segment 必须报错，即使分区索引也缺失；未登记的新分区候选路径可以跳过。
- 单连接暂存保留 SQLite 的原生 `sqlite3.Row`，验证限制下推、超时、提前关闭及临时文件写失败的资源释放。
- 临时文件读取不完整时必须报错，不能把意外 EOF 当作正常完成并静默丢行。
- 通配符列表包含带空格的 `*` 时，排序与 latest 投影也保持全部列；空时序表仍校验投影语法。
- `STRING` 等 SQLite 声明的实际亲和性可能与库的通用类型别名不同；分段统计及旧 manifest 裁剪也须基于物理列类型保守判断，避免正确写入的键在查询时被错误排除。
- 主键归一化同时遵守 SQLite 内置 `BINARY`、`NOCASE`、`RTRIM` 排序规则；无法确认的排序规则拒绝合并或去重，分段统计对非二进制排序规则保守扫描。
- 由 SQLite 解析列声明，排除 `DEFAULT`、`COLLATE` 等约束文字后再计算真实亲和性；无法解析的声明不能静默猜测。
