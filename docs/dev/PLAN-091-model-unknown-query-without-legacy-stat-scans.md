## 范围和设计

1. 普通 select、query、latest、迭代和条件删除在分区元数据裁剪后，以 lightweight legacy 引用定位文件，执行原有 SQL 条件，不主动扫描文件计算 MIN/MAX、COUNT。
2. `iter_batches()` 使用轻量引用；显式 `count_rows()` 只执行必要的行数查询，避免预先重复统计。
3. row segment 已有 manifest 统计仍可用于裁剪。`segments()`、布局/校验等明确诊断保留完整统计；explain 的裁剪决定与实际查询保持一致，不能用额外计算的 legacy 统计宣称实际未发生的裁剪。
4. 缺失的已登记 legacy 文件保留物理引用，由已有缺文件检查报错；合法 segmented 布局不要求 legacy 文件存在。覆盖相关读路径和避免索引/补列操作意外重建缺文件。
5. 不修改公开参数、业务导入脚本、正式库数据，不处理独立的类型推断瓶颈 KI-20261021-1806-002，不提交或推送。

## 风险与自查

已自查：普通查询不依赖 legacy row_count，原 where 仍下推 SQLite；manifest segment 统计的读取不需要数据扫描，应保留。完整诊断和普通执行引用需要分开使用，避免 explain 与实际计划不一致。缺文件处理不能把正常的 segment-only 文件布局误判为损坏。所有性能实验仅向独立临时库写入；测试不依赖墙钟阈值，以禁止统计调用及验证结果防止退化。
