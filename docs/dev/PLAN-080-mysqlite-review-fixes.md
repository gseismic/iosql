# PLAN-080 mysqlite 复审问题修复

- 日期：2026-10-02
- 状态：已完成
- 范围：`iosql.utils.mysqlite` 上一轮 review 列出的全部问题，并检查 SQLite 引擎对低层修复的调用兼容性。

## 目标

修复低层 SQL 接口静默丢写、异构批量写重排、非法批次大小静默无操作、内存 URI 漏拦截、fork 后连接预算/锁状态损坏、连接租约归还时 PRAGMA 不生效，以及构造参数中的零值 PRAGMA 被跳过。

## 实施步骤

1. 在 `Table.execute()` / `execute_params()` 执行 SQL 前调用写入提交策略校验；保留 `insert_all()` 内部事务批量路径的 `commit=False`，避免破坏 SQLite 引擎对分区数据的批量写入。
2. 为异构批量插入改用按输入顺序的连续 key 集合分组，避免 `replace=True` 时跨组重排；校验 `batch_size` 是正整数。
3. 识别 `uri=True` 的 SQLite URI `mode=memory`，继续拒绝连接池无法保证共享状态的内存库。
4. 将 fork 重置改为进程级的一次性处理：在子进程重建连接池与预算同步原语，隔离父进程遗留租约，避免多个池重复清空进程连接计数及继承锁死锁。
5. 归还仍在使用的连接时，按当前 PRAGMA 配置同步连接；新建连接时把合法数值（包括 0/False）规范为 SQL 值并应用。
6. 自审改动与 SQLite 引擎调用链，确认常规文件数据库读取/写入契约及引擎内部事务未被破坏；产出结果文档。

## 兼容性约束

- 文件数据库的持久化格式与既有数据不变，不执行迁移。
- 既有正数 `batch_size`、正数/字符串 PRAGMA 配置保持行为；无效批次大小改为明确报错。
- `Table.execute*` 的 `commit=False` 在池外上下文中显式报错，防止静默回滚；mysqlite 内部受控事务仍允许内部语句不单独提交。
- 用户原有未跟踪 `.zcodeignore` 不纳入改动。

## 验收

- 上述 7 类缺陷在实现逻辑中均被封闭；对每项进行代码级路径复审。
- SQLite 引擎默认文件路径、显式 `commit=True` 删除路径、分区 `insert_all()` 批量事务与正数批次参数均保持兼容。
- 本轮不新增或运行测试；结果文档明确记录此限制及静态复审证据。
