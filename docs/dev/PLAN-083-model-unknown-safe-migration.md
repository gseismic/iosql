## 目标与范围

Database 与 Table 统一 `migrate_to(..., tables=...)`，保留旧单表目标名调用。SQLite、Parquet、PostgreSQL 在迁移期间禁止源/目标的协作读写，完整暂存后校验和发布，发布中断可恢复，提交确认后及时解锁，清理不占业务锁。

涉及公共参数、连接与事务生命周期、全库操作锁、查询流、发布恢复、结果与异常、CLI、示例、README 和 skill 副本。保留独立 mysqlite 工具既有接口；直接绕过主 API 的文件访问不属于协作锁范围。无需提交或推送 Git。

## 当前状态与约束

- 当前迁移直接分批写入正式目标；单表用 target_table、多表用 tables，校验与错误路径存在差异。
- 现有表级锁只能保护单表复合写入；查询对象的消费和流式读取必须接入库级租约。
- 设计审查发现：所有写入也要检查待恢复状态；完成标记与 generation 必须共同原子更新；PG 事务必须由迁移器独占管理；dry-run 必须走源共享锁。
- 普通调用拿不到迁移锁立即报忙；迁移按稳定顺序取得源与目标独占锁，有总等待期限。
- 本地使用完整物理代际与原子路由发布；PG 使用专用连接、服务器事务及管理 schema，不伪装成文件改名。

### 实施前修订：本地物理代际

发现现有 SQLite 空闲缓存连接可能在业务调用结束后继续持有 WAL 文件。只在活跃操作上加库锁、再交换同名物理目录，仍可能让旧连接关闭动作触及新库的同名 WAL 路径。

本地发布改为准备完整的新目标代际，通过单一控制记录原子切换 physical_root/generation/提交状态，旧物理路径不复用。保留未选中表、URI、mode 与返回类型；路径解析、重命名、备份/恢复和身份检查同步适配代际根。加入旧缓存跨发布及 WAL 完整性验证。此修订先于发布器实施，不以目录交换方案继续开发。

## 风险与回退

- 库级锁接入遗漏会破坏维护窗口；应从公共方法及查询消费两端接入，并检查构造时的隐式读写。
- 任何已决定提交的失败必须恢复或拒绝访问，不能自动删除目标；旧目录在持久提交前保留。
- 兼容行为及默认值保持，新增安全语义在文档说明；不以回滚用户改动作为恢复方式。
- 大任务保留计划进度和接续信息，避免将局部实现报告为完整能力。

### 审查修订：分区种类变化与时间单位

源 duration(ms) 或未分区秒单位时间列转 calendar 时必须保留时间数值。运行时 CalendarPartition 目前依赖 Arrow 猜测数字单位，早期 epoch 毫秒会被当作秒；PG calendar BIGINT 边界目前按文本生成。实施前补充：Calendar 运行时可携带明确的数值时间单位，manifest 只在 ms/s 时追加字段；PartitionSpec/恢复传递该单位，PG 根据同一单位生成数值边界。增加早期 epoch、时区、跨后端及重开后剪枝验证，不用改变源数据值来修复布局。

### 审查修订：纯参数校验与目标连接顺序

普通操作的统一屏障会先建立 PG 协调连接。迁移在申请目标锁前，先以源共享租约验证选表及完整目标契约（含运行时分区和时区），避免拼错 specs 或源表名时却先报目标连接失败。随后释放该预检租约，按固定顺序申请源/目标独占锁，并在独占范围重建计划以防源在间隙发生变化；默认维护窗口从独占锁取得后开始。初始源锁和随后所有锁共用等待期限。dry-run 只执行源共享阶段。

### 最终兼容审查：PG 已绑定对象

库级 generation 会覆盖未选中 PG 表，重建缓存时不能让已绑定实例丢失契约。实施前补充：Database 保留 PG 对象缓存，Table 重连后先只读确认关系仍存在，再按同 OID 的本次持久契约或原绑定校验并恢复属性；读取不得自动建表。新打开 PG 对象仍按既有规则显式绑定，调用方事务仍先拒绝。增加选中/未选中旧对象在迁移后继续写入验证。

### 最终 CLI 屏障审查

CLI 的 index/doctor 等命令存在直接使用 mysqlite 扫描物理文件的路径，仅保护 Table 方法仍可能遗漏命令间隙。实施前补充：普通有 source 的命令持完整共享租约；migrate/repartition/rename/backup/restore 自行管理独占边界，web 服务启动不持常驻源租约。restore 在纯路径检查后取得备份源/目标独占锁，再重新判断目标是否存在及 replace/yes 授权，消除预检后目标被创建却遭覆盖的竞态。新增实际互斥与竞态验证。

### 提交状态保留

本地单一控制指针保持常数大小；覆盖一个已经 COMMITTED 的当前记录前，必须先把它按任务 ID 持久归档到稳定协调目录。否则后续迁移清理旧代际后，先前调用发生 fsync/应答不确定的操作者可能无法查明原任务是否提交。归档先于下一次控制替换，清理不得删除历史状态。增加连续发布后历史任务仍可确认的验证；错误给出控制记录位置。

### 缓冲写入屏障

旧 buffered_writer 在 flush 先清空缓冲再调用 Table.write，遇到迁移 DatabaseBusy 会丢失尚未写入的缓冲。实施前补充：append/flush 也遵守库租约，with 上下文覆盖整个缓冲写入窗口以避免每行重复建锁；flush 失败保留缓冲，不自动重试。增加维护窗口拒绝缓冲写入、上下文阻止迁移以及失败缓冲保留的验证。同步补全新目录父项 fsync 和后续发布前已提交任务归档的持久化顺序。
