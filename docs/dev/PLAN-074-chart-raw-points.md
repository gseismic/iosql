# PLAN-074：Charts 全量原始点绘制

日期：2026-09-29
设计：`docs/design/chart-20260929-raw-points.md`
状态：已完成

## 1. 问题

真实浏览器测试发现 Charts 默认仅返回 2,000 个桶均值。对 4,183,200 行的 Binance
K 线指标表，未选 symbol 时还把 8 种资产混成一条平均线，x 坐标使用人工桶中点。
该行为会遗漏分钟数据、抹平尖峰并产生无金融含义的跨资产均值。

## 2. 实施范围

1. 将 line 绘图改成逐行查询与 NDJSON 流式输出，投影 symbol、时间列和指标列；不分桶、不截断。
2. 空 symbol 代表每个 symbol 各自成线；显式单/多 symbol 只画所选资产。
3. 保留原始 x；y 为 null 时保持断点，不当成 0；校验序列时间单调性与点数。
4. 前端流式解析到扁平数组，合并不等长序列的 x 轴并为缺失值填 null；状态明确显示无抽样及点数。
5. 保持 start/end、拖拽缩放、双击复位语义，任何窗口仍返回该窗口全部原始行。
6. 清除直接 candle API 的旧分桶路径；OHLC 图每个时间点保留全部原始 OHLC 值，并避免同一 OHLC 图重复扫描四次。
7. 补充后端与前端回归验证；运行真实浏览器验收并记录实际全范围点数、耗时和视觉结论。
8. 验证客户端中止 NDJSON 请求时，SQLite 有序读取器可在请求清理线程释放只读连接；取消请求不得在服务端产生线程归属异常。

## 3. 验收标准

- 未筛选真实表全范围：总点数精确等于 4,183,200，8 个独立 symbol 序列，逐序列数量与源表一致。
- 单 BTCUSDT 全范围：525,600 个点，x 首尾、y 样本与源表逐行一致。
- 指定 start/end 的接口结果行数、首尾时间与源表条件查询一致；缩放窗口不会按 buckets 采样。
- 浏览器无 JS 异常，图表完整呈现，状态行明确写明「无抽样」及实际点数；抽样字段不再出现。
- null 指标值产生断点而非零值；不同 symbol 不互相求均值。
- candle 接口不返回桶中点或桶内聚合值。
- 测试中途跨线程关闭 SQLite 有序流，并在真实浏览器取消流式请求；清理无异常且连接预留释放。

## 4. 验证步骤

1. 针对小型 SQLite 测试库校验原始行、过滤、多个 symbol、空值和窗口边界。
2. 启动只读 Web 服务，用 Playwright 浏览器访问真实 `kline.factor.iosql`。
3. 抓取网络流与图表状态，比较全范围及 BTCUSDT 的实际点数、首尾时间和已知源数据值。
4. 在浏览器拖拽缩放、双击复位，确认两次请求均精确对应时间范围且无额外回环。
5. 再次 review 后端流迭代、前端多序列对齐、null 值与错误路径；修复发现的问题并写 outcome。
