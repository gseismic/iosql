# PLAN-071：Charts 可视区按需加载（缩放只查窗口）

日期：2026-09-28
状态：已实施（结果见 PLAN-071-chart-viewport-zoom-OUTCOME.md）

## 1. 现状与问题（用户提问：绘图能否只绘制可视区）

PLAN-070 之后绘图链路为：前端进入 Charts Tab 一次性请求
`GET /chart?col&start&end&buckets=2000` → 服务端对该窗口做 SQL 全量聚合
（内存有界，仅返回 ≤2000 个降采样点）→ uPlot 一次渲染。

- **传输/渲染层面**：已经是降采样的（≤2000 点，非原始行）；
- **读取层面**：每次绘制对窗口内全部数据做一遍扫描聚合（SQL 端，线性于
  窗口行数，418 万行约 2s）；
- **交互层面**：uPlot 拖拽缩放/双击复位只改变视口映射，**不会**按可视区
  重新查询——放大后看到的仍是全范围 2000 点的粗采样，且无论视口在哪，
  服务端都只见过"初始窗口"这一次查询。

用户期望：缩放时只读取/绘制可视区数据（局部高分辨率），不做全量读取。

## 2. 方案（前端为主，服务端零改动）

服务端已支持 `start/end/buckets` 且 start/end 触发分区裁剪，可视区查询
只是前端把 uPlot 视口变化转成带窗口参数的重新请求：

1. **视口 → 查询**：给 uPlot 挂 `hooks.setScale`（x 轴刻度变化 = 拖拽缩放
   或双击复位后触发），取 `u.scales.x.min/max` 作为可视区；时间轴按
   `×1000` 换算回毫秒，非时间轴直接用原始 x 值；
2. **防抖 + 去重**：250ms 防抖；与上次已加载窗口近似相等（相对 1e-6 容差）
   则跳过；请求序号守卫，过期响应丢弃；
3. **窗口内重查**：按当前图型（line 单列 / candle 四列）以可视区
   start/end 重新 `fetchSeries`（buckets 不变 → 放大即局部高分辨率），
   复用既有对齐逻辑重建 uPlot data；
4. **原地图更新**：`chart.setData(data)` 复用实例，不销毁重建（避免
   resize 监听与 DOM 抖动）；`setData` 前后置 suppress 标志，防止内部
   setScale 回环触发再次查询；
5. **复位即全量**：双击复位把 x 刻度恢复为初始全范围 → 视口查询退化为
   无 start/end 的全范围重查（与首次绘制一致）；
6. **状态提示**：图下方 note 行显示"可视区加载中…/可视区范围与点数"，
   请求期间复用 spinner 样式。

不做的：滚轮缩放/平移（uPlot 核心无此交互，需引入插件，暂不扩依赖）；
可视区查询的前端结果缓存（同一窗口反复缩放回同一区域会重查，先接受）。

## 4. 测试计划

1. 既有全部 JS 静态契约测试与 web 套件回归；
2. 浏览器实测（临时服务 + 418 万行大表）：进入 Charts 出图 → 拖拽缩放
   → 观察发出带 start/end 的新请求且局部点密度提升 → 双击复位回到全量；
3. 关闭 JS 回环：缩放后 setData 不再触发第二次查询。

## 5. 验收标准

- 拖拽缩放后仅按可视区发起新查询（请求带 start/end），局部曲线点密度
  随放大提升；
- 双击复位回到全范围数据；
- 回归测试全绿，无请求风暴（防抖 + 去重生效）。
