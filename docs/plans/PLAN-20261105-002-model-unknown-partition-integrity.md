## 主要风险与回滚

- 已有表的强制切换将从允许改元数据改为拒绝，以阻止漏查；兼容需求通过新目标重分区满足。
- PostgreSQL 分区验证和事务锁可能增加写入成本；应检查测试和代表性性能，避免不必要的全数据扫描。
- 新建负数分区采用可区分正负的名称；已存在旧名称时按已核验的原生边界复用，不重命名、不搬动数据。
- PostgreSQL 旧表首次写入需要表所有者权限以添加契约约束；仅凭已有有限分区边界不能唯一还原旧策略，须由调用者声明并核对原策略。
- 历史 PG 尾桶和旧时间契约不可盲目覆盖：无法证明安全时保留数据、提示迁移并明确未自动处理的范围。
- 纯日期路由版本必须持久化并随迁移传播；已有布局未经显式迁移不切换，混合版本应拒绝写入。
- 测试使用独立临时目录及 PostgreSQL 临时实例；如需回滚，仅撤销本次改动，不覆盖上一任务的未提交改动。问题事件保持追加历史。
