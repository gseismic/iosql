## 目标与范围

- 让 `iosql migrate` 启动后持续报告当前阶段，源表和本地暂存目标的行数统计尽可能显示已统计物理文件数，复制时显示每表已复制与源表总行数；耗时阶段定期提示仍在处理及耗时，不编造未知总量。
- 保留最终 JSON 写入标准输出的契约；阶段信息仅写入标准错误，重定向标准输出时仍可解析结果。预览和错误路径也有明确状态。
- 在 `iosql migrate --help` 给出可复制的实际命令示例，补充 README 中的进度说明。
- 不改变 `Database.migrate_to` 等公开 API 签名、迁移数据与发布协议；不接触用户正在运行的迁移及其文件，不提交或推送。

## 现状、方案和约束

- CLI 在 `db.migrate_to()` 返回后才输出 JSON；统一迁移在复制前逐表统计源行数，完成暂存后再次统计目标和校验，耗时可能很长。
- 可选方案一是在公开迁移 API 新增进度回调；这会扩大用户 API，且目前需求仅为 CLI。方案二是在迁移内部用按上下文隔离的私有观察器传递阶段、计数和批次事件，由 CLI 负责输出及节流。选择方案二，未订阅时保持原有行为。
- SQLite/Parquet 统计使用同一逐物理文件流程；PostgreSQL 单次计数无法报告内部进度，只报告阶段和耗时。已有总行数指当前表，不能当作整个迁移百分比；复制行数可能与目标写入行数不同。
- 为避免长时间单个文件、锁等待、完整性验证或发布没有反馈，在 CLI 运行期间使用可结束的轻量提示线程。观察器和输出失败不得改变迁移结果；无需新增文件或日志。
- 保留此前工作区改动，并避免影响正在运行的旧进程；已有进程不可能加载之后修改的代码。

## 实施步骤

1. 增加内部进度上下文与事件，在源统计、本地目标统计、复制、校验和发布路径上报告真实阶段及计数；明确干运行与正式迁移的区别。
2. CLI 将即时阶段、限频进度和长阶段周期提示输出到标准错误，结束时清理提示线程；最终 JSON 保留在标准输出。
3. 在帮助加入可运行示例，并在 README 说明进度输出、逐表统计与校验的含义。
4. 对独立临时库验证复制、预览、无进度订阅、标准输出 JSON、标准错误进度、异常与观察器清理，以及帮助示例的实际可复制性；运行相关迁移与 CLI 回归测试。

## 实施前自查、风险与完成标准

- 观察器上下文在异常时恢复，线程退出后不能残留输出；任何输出异常不得终止数据迁移，且不暴露 URI 凭据。
- 较慢的分区列表获取、单文件计数、目标完整性验证和发布均有阶段或耗时提示；不同表和预览不显示虚假的整体百分比。频繁批次和文件事件应节流。
- 不修改 `count_rows()` 的对外签名和结果；物理文件计数发生在原有统计循环内，其他调用和引擎语义不变。
- Rich 与普通帮助下命令可复制并执行；标准输出保持可被 `json.loads` 解析。对非终端输出也提供可重定向的逐行提示。
- 发现验证失败先修复；回滚只涉及本任务新增修改，不覆盖已有变更。
