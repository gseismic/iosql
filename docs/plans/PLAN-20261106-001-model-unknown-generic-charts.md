## 目标、范围和约束

修复多于 32 组数据时图表默认请求失败的问题，并按用户要求使用通用条件、X/Y 列与类型决定图型，不把金融标的作为通用图表的必填概念。参考用户指定的 mchart3.js 和示例；保留原始点、已有图表 API 和 OHLC 四线。用户原库与现有服务只读，不重启或写入；不修改 `GOAL.md`。

## 当前状态与依据

现有页面进入时自动请求全表，按契约的 `symbol_column` 分线，上限 32；指定原库一分钟窗口时空筛选返回超限错误，指定其中一个实际存在的值返回 1 条原始记录。当前界面写死 symbol/start/end，缺少通用轴与条件选择。旧 `GET /chart` 已被测试及历史设计依赖；mchart3 折线默认可能降采样，必须关闭。

## 实施步骤

1. 按设计新增通用只读图表请求，复用条件解析和流式列投影；保持旧 GET 完全兼容，覆盖类型、分组、排序及错误边界。
2. 将 mchart3 必需模块打包为可离线分发的静态资源，记录版本来源；实现通用配置、类型自动选择、原始点绘制、缩放与取消。
3. 更新项目使用说明及静态资源版本；为数值、类别、分组、筛选、空值、超限、并发和旧接口补充行为回归。
4. 使用隔离库和用户运行的只读原库进行浏览器验证，运行相关测试及打包检查，复核变更。

## 验证与完成标准

- 打开 Charts 不自动请求全表；任意字段筛选后可绘制，未筛选可由用户主动绘制。
- 时间/数值 X 与数值 Y，以及含类别 X 或 Y 的场景均按类型显示；无静默抽样、聚合或混组，空值语义明确。
- 旧 GET 图表和 OHLC、筛选、缩放、只读安全行为不回归；超过分组上限明确提示。
- 有实际大表原库的小窗口手测，不能把小窗口耗时推断为全表性能；依赖资源打入可安装包，无运行时本地路径或外网依赖。

## 风险与回滚

原始全量点可能使浏览器耗时或内存增长；明确提示用户先筛选。事件流需处理取消和过期响应，避免旧配置覆盖新图；缩放请求使用已绘制配置的快照。若出现兼容问题，按本次差异撤销新增 POST、前端和资源，保留原 GET 与历史数据。

## 实施前自查

比较过 GET 追加复杂 JSON 与新增 POST，选择后者以保留现有接口并表达条件。计划不引入 symbol 专属选择、不预扫描全表、不截断或降采样。先测试明确的数值与文本类型，其他类型给出错误；任何实质范围变化先更新本计划。
