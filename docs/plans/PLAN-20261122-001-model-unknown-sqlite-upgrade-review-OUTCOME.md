## 验证结果

环境为 macOS、Python 3.11.15、SQLite 3.53.0、NumPy 2.4.6、DuckDB 2.0.0、PostgreSQL 14.19、pytest 8.4.2。CLI 采用兼容的 Typer 0.12.5 和 Click 8.1.8。测试均使用临时库。系统盘空间不足时改在独立内存卷上的精确源码副本验证。临时插件只重定向两个旧测试模块硬编码的测试目录。

| 验证 | 结果 |
| --- | --- |
| 最终 SQLite、Parquet、mysqlite、时序契约、CLI 与单连接专项组合 | **311 通过**，包含全部 43 项新增回归。 |
| DuckDB 1.1.0 最低支持版本 | **116 通过**。随后单连接四种源/目标组合也全部通过。 |
| 禁用 NumPy 导入后的 mysqlite 回归 | **35 通过，2 跳过**。跳过项需要 NumPy。 |
| 扩大全量 `python -m pytest -q tests` | **1754 通过，98 跳过，3 失败，0 错误**。共收集 1855 项。43 项新增用例均通过。 |
| 父版本实库升级 | 分别用父版本生成错位的 REAL 主键分区、旧版 NumPy BLOB 主键。新版拒绝可能产生重复的写入，显式迁移后验证数据及重复覆盖结果。 |
| 静态及差异检查 | 变更 Python 文件的 ruff、Python 3.9 语法解析与 `git diff --check` 通过。12 个变更 Python 文件与最终专项使用的副本逐文件核对一致。 |

全量的三项失败包括基准已存在的 PostgreSQL 重复 symbol 对照，以及两项 Parquet 单连接用例在首批返回前超过 100 ms 测试预算。后者改为首批返回后推进单调时钟，保留运行时超时断言、资源释放与复制断言。最终 311 项组合和 DuckDB 1.1.0 的单连接复测均通过。全量运行使用相同的生产代码。98 个跳过项包括已废弃接口、独立密码认证配置、Playwright Chromium、文件系统条件和 Windows 专用场景。

旧库验证使用 `git archive f4cd843` 的独立源码。宽表对照使用 2 万行 × 128 列。分区路由与分组的额外峰值为父版本 0.17 MiB、审查基准 64.50 MiB、修复后 0.17 MiB。无 NumPy 的原生批量绑定耗时中位数从 0.442 秒降到 0.199 秒。
