## 当前依据与设计选择

- mysqlite 的整次批量事务不被 `database.in_transaction()` 识别，SQL 翻译异常时会 rollback 全部先前批次。优先在需要 schema evolve 时预先补齐当前批次列，避免失败后重放已经部分成功的语句组；保持稳定 schema 的热路径。
- NumPy 推断已转换局部标量，但参数未转换。公共绑定路径采用原生值转换，不引入 NumPy 必选依赖，也不全局注册 sqlite3 adapter。
- Python 全局排序复用 `_SqliteSortKey` 存储类秩和 SQLite 内置 collation；latest/compact 复用现有亲和性及等价键机制，避免再次用原始 Python 值判断。
- REAL 分区键路由必须采用物理亲和性后的值；不能因舍入导致实际存储值被裁掉。保留批量处理且不修改调用者行对象。
- 统计采用有界缓存并清除同文件旧版本，保护并发访问；关闭表时释放属于该表的缓存。
- 手动建表复用正常写入的逻辑元数据登记；检查已有契约与布局，避免生成不可达或错误分区的文件。

## 风险、回滚与实施前自查

- 事务：预补列需与数据处于同一个事务；不能提前提交或重复执行当前批已写行。
- 比较：NOCASE 仅折叠 ASCII，NUL、RTRIM 空格、文本数值亲和性与混合存储类必须以 SQLite 为对照；不要把等价判断与排序简单混用。
- 元数据：手动建表不应覆盖已有逻辑表，不应提前登记未成功创建的物理文件；row segment 不能伪造 legacy 主分区。
- 兼容：Parquet 继承部分 SQLite 实现，应按后端保留其既有比较语义。
- 资源：缓存锁不覆盖数据库查询，避免锁顺序死锁。
- 回滚：仅撤回本次代码及测试修改；所有测试使用临时库，不操作现有业务库。
