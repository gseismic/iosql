## 目标、范围和不处理事项

按 `docs/design/local-uri-engine-20261106-overview.md` 实施本地库自动识别、类型一致性保护、新旧显式前缀、写入和迁移选择及 Web 使用。保持现有业务数据和跨后端迁移语义；不改写用户的现有数据库、不静默转换格式，也不扩展当前不支持的 PostgreSQL 维护操作。

## 当前状态和依据

`Database` 按 URI 前缀选择引擎；CLI 裸路径固定为 SQLite，表枚举过滤其他引擎。前一轮以临时库验证，同名已写表存在表级拒绝，但不同表可混用；SQLite 空表先声明后被 Parquet 接管，再由原句柄写入可令 Parquet 数据不可见。库级缺少可持久识别的类型。

## 步骤

1. 设计并实现类型标记、旧库只读识别、URI 解析、严格错配与跨进程初始化锁；覆盖已有句柄和空表竞争。
2. 接入 `Database`、表写入和创建、迁移目标/恢复、快照与重命名；保留旧前缀并支持 `iosql+` 别名和泛型本地 URI。
3. 接入 CLI Web 和迁移，支持自动识别已有路径、显式前缀及新目标引擎选项；不支持的功能给出明确错误。
4. 增加跨引擎、路径、兼容、空库、混合/损坏、并发、发布恢复和 Web/CLI 的实际行为测试；更新使用文档。
5. 完成自查、相关测试和必要的全量回归，记录结果。

## 验证和完成标准

旧/新 URI 均可按相同引擎读写和迁移；真实已有库能用普通路径打开；显式错配、混合库和无法识别的库明确失败；两个引擎不能通过不同表或旧句柄混写。新建空库身份持久，SQLite 代际和 Parquet 平坦发布及恢复仍正确，迁移 dry-run 不连接目标。Web 图表在 Parquet 的真实或隔离副本上可读。相关测试、共享行为全量回归和差异检查通过。

## 风险与回滚

标记落盘和恢复顺序、旧版/新版本并发、只读目录权限、目录复制和路径解析是主要风险；使用临时库测试，不原地处理用户数据库。实现若出现错误可还原本次代码及文档改动；已由新版本创建的库保留原数据及标记，先检查身份后使用明确后端读取。外部旧版本不遵守新标记，不能提供跨版本写入协调保证。
