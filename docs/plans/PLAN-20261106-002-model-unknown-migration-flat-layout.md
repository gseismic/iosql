## 现状与约束

- 本地迁移当前在 `iosql/migration.py` 的 `LocalPublisher` 构造完整代目录，协调状态通过父目录 `.iosql-locks` 指向代目录；普通表创建直接使用根目录。
- 迁移支持已有目标、保留未选中的表、多个表及失败恢复；更改布局不能简单地逐表裸移动，更不能在切换时暴露部分数据或在已存在目标时丢失数据。
- SQLite 元数据可能有活动或空闲连接，旧连接及 WAL 路径重用、跨进程协调、故障恢复、跨文件系统和已有布局必须考虑。实际迁移目标目前只有一个已提交代，目录与数据在同一文件系统。
- 生产目录整理需要在库级独占锁内进行，事先确认源代、发布状态、文件身份、目标无冲突及无活动数据句柄；关键步骤采用可恢复或失败时拒绝访问的记录，不能删除用户数据或重写 Parquet 文件。

## 自查、验证与风险

- 新、旧目标不得因改用平坦布局而损失未选表、错误处理、行数验证、协作锁或崩溃恢复；区分普通客户端和绕过锁的文件访问。
- 普通数据库目录包含 SQLite 元数据，替换已有目标时旧连接和 WAL 不能与新内容冲突。若原子切换所需条件无法证明，先解决设计，不直接发布生产更改。
- 正式库只做同文件系统目录重命名及少量协调记录调整；转换前后比对完整数据文件清单和文件身份，另验证 API 读取。没有保证的逐字节完整性应如实说明。
- 任一发布或转换中断时保留数据和恢复依据；正式库一旦发现身份变化或已有冲突立即停止，绝不覆盖。用户已明确授权整理该指定库，不扩展到其他库。

## 2026-11-06 01:31 实施补充和设计自查

- 同一 NTFS/FUSE 目标盘不支持 Linux `RENAME_NOREPLACE`；一次性整理脚本通过独占预留空目录、持库级锁和身份核对避免覆盖，并在该盘演练三个中断阶段。用户库已按授权整理：表直接位于根目录；21,906 个数据文件的相对路径、设备、inode、大小和修改时间一致，三个 Parquet 样本 SHA-256 一致；逻辑表、9,984 个分区和样本读取通过。仅移动表目录和管理目录，未复制或重编码业务数据。
- 原提交代的标记和控制记录保存在目标父目录 `.iosql-locks` 下，原地数据不重复保存。临时脚本位于 `/tmp/iosql-reorganize-parquet-layout.py`；故障时控制记录拒绝正常访问，脚本可根据身份核对继续完成。
- 后续 Parquet 发布拟采用持独占租约的持久恢复记录。新表整体进入根目录；已有表保留原 SQLite 元数据文件 inode，通过 SQLite backup 在原文件事务性更新元数据，并在恢复屏障下切换数据目录。空闲旧连接无需被路径替换，下一次 iosql 操作按 generation 刷新；未选中表留在原位。临时原型已验证已有表、旧连接、未选中表及后续写入。
- 自查：不得把多表逐项切换伪称为无条件的文件系统原子操作；一致性依赖 iosql 协作锁和故障恢复屏障。每个阶段需验证目录身份并支持重复恢复；目录及元数据持久化、清理与路径重用、跨文件系统工作区、根挂载点和异常处理中断均需测试。绕过 iosql 的原始文件访问不在该屏障内。
