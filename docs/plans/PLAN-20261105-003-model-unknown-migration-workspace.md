## 目标、范围与非目标

- 本地 SQLite/Parquet 目标默认使用目标所在文件系统中的独立工作区，减少跨文件系统迁移时的额外复制；适用于 CLI 和 Python 的 `migrate_to` / `save_as`。
- 显式 `temp_dir` / `--temp-dir` 保持原有语义；PostgreSQL 目标没有本地目录，继续使用原有默认策略。
- 不运行用户实际数据迁移，不修改用户数据库，不修改其他任务的未提交改动，不提交或推送。

## 现状、方案和兼容性

- `iosql/migration.py` 当前默认将工作区放在本地源的 `__iosql_migrations__` 下；跨盘发布时需完整复制到目标侧。用户可显式选择工作区，但默认跨盘性能不符合当前需求。
- 可选方案一是仅修改 CLI 的默认值，但会造成 CLI 与 Python API 行为不一致；方案二是在共同迁移器根据目标选择工作区。选择方案二，保持接口签名不变。
- 普通本地目标将工作区放入目标父目录的 `.iosql-locks/<目标标识>.workspaces/<任务ID>`；若目标根目录自身是不同设备的挂载点，则将工作区放在目标内的 `__iosql_migrations__/<任务ID>`。内部管理目录不参与目标快照；用户显式传入目标内部的 `temp_dir` 仍按原规则拒绝。
- 本地目标先执行已有预检，再创建工作区，避免挂载点场景的管理目录影响目标身份检查；源、目标独占锁及发布/恢复协议保持不变。预览不创建工作区。
- 默认路径变化会改变磁盘空间和权限需求；不自动回退到源盘，避免用户误以为仍在目标盘。失败工作区保留供检查，成功只清理本任务目录。
