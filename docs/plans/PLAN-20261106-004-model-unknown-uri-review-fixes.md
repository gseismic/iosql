## 目标与范围

修复缓存表访问阻塞其他表写入、迁移目标识别不遵守 `lock_timeout`、带标记空库无法备份或作为恢复目标、创建库选项无效时留下标记，以及 Parquet 兼容图表接口不支持数字文本轴和 64 位文本时间戳的问题。保留既有 URI、并发保护、迁移恢复和图表行为，不修改用户的实际业务数据库。

## 依据与约束

用户提供的 Review 指出六个可复现的行为回归；当前工作区是前一任务尚未提交的实现，不能覆盖或回滚。目标识别与后续迁移锁应共用同一有限等待预算，超时保持迁移接口的错误语义。空库身份依赖有效标记，不能把普通空目录或错误类型当作可覆盖的库。图表修复须保留错误数据校验、筛选与排序，不只覆盖正例。

补充自查发现相同的等待预算缺口还存在于 CLI 的源库自动识别和源表预检；一并纳入修复，保证用户指定的迁移锁等待预算从源库识别开始连续生效。

## 实施步骤

1. 针对六个问题分别补充行为级回归，必要时先用隔离库验证触发条件。
2. 调整缓存表访问和初始化验证，保留类型一致性与并发保护；使有效标记的空库可备份、恢复，普通空目录继续拒绝危险替换。
3. 将迁移的剩余超时预算传递给源库识别、目标识别及源表预检所需的库租约和类型锁，复核超时异常、零等待、恢复与 dry-run 行为。
4. 修复 Parquet 兼容图表的文本轴检查和数值排序，验证 64 位毫秒时间戳、数字日期、异常值、筛选与分组。
5. 完成代码自查、相关测试和适当的完整回归，更新计划结果与索引。

## 验证与完成标准

两张表经 `db.table()` 调用也能并行写入；目标独占租约或类型锁竞争时，迁移遵守整个 `lock_timeout` 并返回约定的超时异常；空库备份/恢复及无效构造器参数的重试符合预期。SQLite 与 Parquet 兼容图表分别覆盖数字文本日期、13 位时间戳和无效文本，返回正确状态、顺序及数据点。原有类型错配、损坏目录保护和迁移恢复测试不回归。

## 风险与回滚

锁顺序和等待预算可能引入死锁或改变报错类型；快速访问缓存表不能绕过身份保护；放宽空库校验不能降低普通目录的保护；更改 SQL 类型不能导致 SQLite 行为变化。使用临时目录与隔离服务验证；如需回滚，只还原本次修复相关变更，保留此前工作区内容。
